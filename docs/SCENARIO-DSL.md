# Формат сценария и правила движка

Спецификация ядра «ЭКИПАЖ 400». Это контракт между тремя вещами:
игровым клиентом, редактором методиста и сервером, который пересчитывает
результат. Всё остальное в продукте — надстройки над этим файлом.

Формат намеренно открытый и человекочитаемый: сценарии лежат в git
у заказчика, правятся глазами при необходимости и не требуют нашей платформы,
чтобы быть прочитанными.

---

## 1. Принципы

1. **Граф — источник истины.** Ветвление, оценка и вклад в компетенции
   заданы данными, а не кодом. Ни один сценарий не требует правки клиента.
2. **Детерминированность.** Одна и та же последовательность выборов с теми же
   таймингами всегда даёт один и тот же результат. Без этого нельзя ни
   пересчитать очки на сервере, ни сравнить двух проводников, ни допустить к работе.
3. **Нет тупиков.** Любой узел достижим из `entry`, из любого узла достижим
   хотя бы один терминальный. Проверяется валидатором до публикации.
4. **Таймаут — это ветка, а не поражение.** У каждого узла с лимитом обязана
   быть ветка `onTimeout`.
5. **Версия неизменна.** Опубликованная версия сценария неизменяема. Правки
   создают новую версию; прохождения хранят номер версии, по которой шли.

## 2. Верхний уровень

```jsonc
{
  "schema": "ekipazh-400/scenario@1",
  "id": "med-01",
  "version": 3,                 // растёт при каждой публикации
  "status": "published",        // draft | published | archived
  "title": "Вагон 4, потеря сознания",
  "summary": "Пассажир теряет сознание на скорости 380 км/ч.",
  "mode": "leg",                // trip — полный рейс, leg — один инцидент
  "difficulty": 3,              // 1..5, для подбора
  "estimatedSec": 210,          // ориентир для списка сценариев

  "context": {                  // мир, в котором происходит инцидент
    "line": "vsm-msk-spb",      // описание инфраструктуры, см. docs/LINE.md
    "service": "express-day",   // рейс: расписание и направление
    "startKm": 126,             // километр, на котором начинается эпизод
    "car": 4,
    "comms": true,              // свободен ли канал связи на входе
    "flags": []                 // произвольные метки мира
  },

  // Скорость, время суток, расстояние и время до ближайшей остановки,
  // тормозной путь — НЕ поля контента. Они считаются физикой линии по
  // километру и обновляются на каждой секунде рейса, в том числе пока
  // игрок думает. Методисту нечем ошибиться: в контенте нечему расходиться.

  "competencies": ["safety", "medical", "comms", "empathy", "speed"],

  "state": {                    // стартовые значения шкал
    "safety": 100,
    "loyalty": 60,              // лояльность ключевого пассажира
    "carMood": 70,              // настроение вагона
    "stress": 20                // скрытая
  },

  "entry": "n-start",
  "reference": ["n-start", "n-call", "n-doctor", "n-report", "n-end-good"],
  // ^ эталонный путь по СОП. Показывается только в разборе.

  "nodes": { /* см. раздел 3 */ },

  "authoring": {
    "author": "Методист депо ВСМ",
    "sop": ["СОП-14 «Медицинский инцидент в пути следования»"],
    "assumptions": "Формулировки СОП — допущение команды, требуют сверки.",
    "updatedAt": "2026-09-20T10:00:00Z"
  }
}
```

Поле `assumptions` обязательно, если контент содержит невыверенные
регламентные формулировки. Оно выводится в интерфейсе — мы не выдаём
собственные допущения за действующий регламент.

## 3. Узлы

Общая часть у всех типов:

```jsonc
{
  "type": "dialog",
  "speaker": "Пассажирка, место 12А",     // необязательно
  "text": "Мужчина в 14-м ряду не отвечает! Он побледнел!",
  "media": "car4-aisle",                  // ключ иллюстрации, необязательно
  "limitSec": 15,                         // лимит на решение; 0 — без лимита
  "onTimeout": "n-late",                  // обязателен при limitSec > 0
  "onEnter": { "stress": 15, "comms": false },  // эффекты входа в узел
  "hint": "Пункт СОП-14.1",               // подсказка, скрыта в «Экзамене»
  "choices": [ /* ... */ ]
}
```

### 3.1. Выбор

```jsonc
{
  "id": "c-call",
  "text": "Нажать кнопку связи: «Вагон 4, медицинский, нужен ЛНП»",
  "costSec": 12,                          // цена действия в секундах рейса
  "requires": { "comms": true },          // условие показа; иначе вариант скрыт
  "keywords": [                           // словарь свободной речи
    "доложить", "кнопка связи", "лнп", "вызвать медиков", "скорая"
  ],
  "effects": {
    "safety": 8,
    "loyalty": 4,
    "carMood": 2,
    "stress": -5,
    "competency": { "comms": 12, "safety": 8 }
  },
  "sop": "СОП-14.1 п.3",
  "feedback": "Верно. Доклад — первое действие: он запускает медиков на Тверь.",
  "mentorNote": "Не тратьте время на самостоятельный осмотр до доклада.",
  "next": "n-doctor"
}
```

| Поле | Смысл |
|---|---|
| `costSec` | Сколько секунд рейса стоит действие. Прибавляется к времени раздумья |
| `requires` | Показывается ли вариант; сравнение с текущим состоянием мира. Кроме флагов и связи принимает `minLeadSec` (пока до остановки не меньше стольких секунд) и `maxSpeedKmh` / `minSpeedKmh` |
| `keywords` | Как проводник скажет это своими словами. Используется в режиме «Живой разговор»; вес выше, чем у слов самого `text`. Валидатор предупреждает, если словаря нет или он не отличается от соседних вариантов. См. `docs/INTENT.md` |
| `avoid` | Слова, наличие которых говорит против этого варианта. Заплатка для узлов, где отрицание меняет смысл |
| `effects` | Дельты шкал и вклад в компетенции. Шкалы зажимаются в 0..100 |
| `sop` | Пункт регламента. Показывается только в разборе |
| `feedback` | Объяснение. Показывается сразу либо в разборе — зависит от режима |
| `mentorNote` | Комментарий наставника, пишется методистом один раз |
| `next` | Следующий узел |

### 3.2. Типы узлов

| `type` | Ввод игрока | Дополнительные поля |
|---|---|---|
| `dialog` | Один выбор из списка | — |
| `checklist` | Отметить действия в правильном порядке | `items[]`, `correctOrder[]`, `partialCredit` |
| `spatial` | Клик по схеме вагона | `map`, элементы в `items[]` с полями `x`, `y`, `r` в долях 0..1 |
| `radio` | Собрать доклад из блоков | `slots[]`, `blocks[]`, `required[]` |
| `sort` | Расставить приоритеты | `items[]`, `correctOrder[]` |
| `outcome` | Ничего, терминальный узел | `verdict`, `summary` |

Все типы сводятся к одному интерфейсу: узел возвращает набор выбранных
идентификаторов и потраченное время. Поэтому оценка, античит и статистика
у всех типов общие, а новый тип узла добавляется одним рендерером.

**Одиночный и множественный выбор различаются местом перехода.**
У `dialog` переход задан на каждом варианте (`choice.next`) — варианты ведут
в разные ветки. У `checklist`, `radio`, `sort` и `spatial` игрок отмечает
несколько элементов сразу, поэтому переход задан на самом узле (`node.next`),
а элементы несут только эффекты. Валидатор требует `node.next`
у множественных типов и `choice.next` у одиночных.

`spatial` — тот же множественный выбор, только элементы дополнительно несут
координаты `x`, `y`, `r` в долях 0..1. Одна механика оценки на все формы
ввода: новый тип узла добавляется одним рендерером, а античит, статистика
и разбор работают без изменений. Доли, а не пиксели, выбраны намеренно —
схема одинаково работает на телефоне и на проекторе, а при переносе в 3D
координаты не придётся пересчитывать.

**Порядок отметок оценивается.** `correctOrder` задаёт эталонную
последовательность, `orderBonus` — что начисляется за её соблюдение,
`partialCredit: false` требует точного совпадения (по умолчанию бонус
начисляется пропорционально доле верных позиций). Пропуск элемента
из `required` бьёт по безопасности и коммуникации: неполный доклад
не запускает никаких действий, и это должно быть видно в числах.

### 3.2а. Условия, привязанные к физике

```jsonc
"requires": { "minLeadSec": 300 }   // пока до остановки не меньше пяти минут
"requires": { "maxSpeedKmh": 40 }   // только на стоянке или малом ходу
```

`minLeadSec` — это точка невозврата. Диспетчеру нужно время: согласовать
продление стоянки, вызвать бригаду к платформе, довести решение до дежурного
по станции. Когда до остановки остаётся меньше — заказывать поздно, и вариант
исчезает не по таймеру, а потому что состав прошёл нужный километр.

`maxSpeedKmh` описывает то, что физически нельзя делать на ходу: перемещать
пассажира без сознания, открывать наружные двери. Экстренное торможение
с рабочей скорости — это больше шести километров, и начинается оно мгновенно.

### 3.3. Узел, недоступный в текущем состоянии мира

```jsonc
{
  "type": "radio",
  "text": "Связь с начальником поезда. Соберите доклад...",
  "requiresWorld": { "minLeadSec": 300 },
  "elseGoto": "n-window",
  "elseReason": "До станции меньше пяти минут: диспетчер уже не успеет согласовать медиков."
}
```

Это не то же самое, что скрытый вариант. Вариант «доложить по связи»
прячется, когда канал занят; а целый узел «сеанс связи с диспетчером ради
медиков на станцию» после точки невозврата не просто теряет варианты — его
не существует, и рейс должен уйти в ветку «окно упущено». Без этого мир
получается непоследовательным: заказывать поздно, а экран заказа открывается.

Движок разрешает узел до того, как игрок начнёт думать, и записывает
переброс в ленту событий разбора. Цепочка обходов ограничена пятью шагами,
чтобы ошибка в контенте не превратилась в бесконечный цикл.

### 3.4. Терминальный узел

```jsonc
{
  "type": "outcome",
  "verdict": "good",        // good | partial | bad
  "text": "Медики встретили состав в Твери. Пассажир в сознании.",
  "summary": "Доклад прошёл до потери связи, помощь оказана в пределах золотого часа."
}
```

`verdict` не заменяет оценку — оценка считается из накопленных шкал и
компетенций. Это только нарратив.

## 4. Модель времени

Главная механика продукта. Часы рейса идут не по реальному времени игрока,
а по формуле:

```
Δt_рейса = min(время_раздумья, limitSec) + costSec(выбранного варианта)
```

Время раздумья считается с точностью до 0,1 с и **сохраняется в прохождении** —
без него сервер не сможет пересчитать результат.

Из `Δt` следуют три вещи:

1. **Прогресс рейса.** `context.elapsedMin` растёт, `remainingMin` падает.
2. **Событийные триггеры мира.** Список `worldEvents` сценария:

```jsonc
"worldEvents": [
  { "atElapsedSec": 40,  "set": { "comms": false }, "toast": "Канал занят: ЛНП на связи с диспетчером." },
  { "atElapsedSec": 150, "set": { "flags": ["filmed"] }, "toast": "Кто-то снимает вас на телефон." },
  { "afterMissedStop": "Тверь", "goto": "n-no-stop" }
]
```

   Так медлительность закрывает варианты и открывает ветки — время
   становится ветвлением, а не штрафом.

3. **Компетенция «Скорость решения».** Считается по суммарной потере
   относительно эталонного времени сценария, а не по абсолютной скорости:
   торопливость с ошибками не должна выигрывать у обдуманности.

Кроме шагов, часы рейса двигают два действия игрока, и оба лежат в пути
отдельными списками — иначе сервер не смог бы повторить расчёт:

```jsonc
"breaths": [{ "afterStep": 1 }],   // «Вдох»: −20 стресса, +4 с рейса
"reveals": [{ "atStep": 2 }]       // «Показать все варианты»: +3 с рейса
```

## 5. Стресс

Скрытая шкала 0..100. Источники прироста: `onEnter` узлов, эффекты выборов,
срабатывание таймаута (+15), потеря связи (+10).

Влияние на интерфейс:

| Стресс | Что происходит |
|---|---|
| 0–39 | Обычный интерфейс |
| 40–69 | Периферия экрана темнеет, лимиты визуально ускоряются |
| 70–100 | Показываются только 2 варианта, остальные — под «показать все» (стоит 3 с) |

Действие **«Вдох»** доступно всегда: `-20` стресса, `+4 с` к часам рейса.
В разборе стресс раскрывается графиком с отметками, где он рос.

Это не косметика: сужение выбора при высоком стрессе — воспроизведение
реального эффекта, и именно так оно объясняется игроку в разборе.

## 6. Прохождение (что уходит на сервер)

Клиент **не считает и не отправляет очки**. Он отправляет путь:

```jsonc
{
  "scenarioId": "med-01",
  "scenarioVersion": 3,
  "mode": "leg",
  "startedAt": "2026-09-27T08:12:03Z",
  "finishedAt": "2026-09-27T08:15:41Z",
  "steps": [
    { "node": "n-start", "choice": "c-call",  "deliberateMs": 4200 },
    { "node": "n-doctor", "choice": "c-ask",  "deliberateMs": 9100 },
    { "node": "n-report", "timeout": true,    "deliberateMs": 15000 }
  ],
  "breaths": [{ "afterStep": 1 }],
  "client": { "offline": true, "queuedAt": "2026-09-27T08:15:42Z" }
}
```

Сервер **проигрывает этот путь по своей копии графа версии 3** и сам считает
шкалы, компетенции, время и ачивки. Отклоняется всё, что невозможно:

- узла или ребра нет в этой версии графа;
- `deliberateMs` больше `limitSec` без пометки `timeout`;
- `deliberateMs` неправдоподобно мал (< 250 мс) на большинстве шагов;
- сумма шагов не соответствует интервалу `startedAt`…`finishedAt`
  (с допуском на офлайн-очередь);
- вариант, скрытый по `requires` в этом состоянии мира.

Отклонённое прохождение не пропадает: оно сохраняется как `disputed`
и видно методисту. Молча терять результат сотрудника нельзя — он
потратил на него время.

## 7. Оценка

```
score  = безопасность × 2 + лояльность + настроение вагона
       + бонус за время (до 100) + бонус за соответствие эталону (до 100)

итог % = (score − худший путь) / (лучший путь − худший путь) × 100
```

Нормировка идёт по **диапазону**, а не по одному потолку: ноль — худший
проходимый путь этого графа, сто — лучший. Обе границы считаются перебором
всех путей и одинаковы для всех игроков, поэтому сравнение остаётся честным.

Так сделано не для красоты. Шкалы стартуют высоко (безопасность 100),
и при делении только на потолок даже безнадёжное прохождение давало больше
восьмидесяти процентов — метрика переставала отличать сильного проводника
от слабого и становилась бесполезной для допуска.

Но **очки — вторичны**. Первичен профиль компетенций:

```
competency[k] = clamp(Σ effects.competency[k]) / maxВозможный[k] * 100
```

`maxВозможный[k]` считается по графу заранее (лучший достижимый путь) —
поэтому 100 % по компетенции означает «нельзя было сыграть лучше»,
а не «набрал много».

Итог рейса: лепестковая диаграмма, шкалы, потерянное время, список
достижений, ссылка на разбор.

## 8. Валидатор редактора

Публикация блокируется, пока есть ошибки:

| Проверка | Уровень |
|---|---|
| Недостижимый узел | ошибка |
| Тупик: узел без `choices` и не `outcome` | ошибка |
| `limitSec > 0` без `onTimeout` | ошибка |
| `next` указывает на несуществующий узел | ошибка |
| Эталонный путь `reference` непроходим | ошибка |
| Компетенция объявлена, но нигде не начисляется | предупреждение |
| Все варианты узла ведут в один узел с одинаковыми эффектами | предупреждение |
| Нет ни одного узла с `sop` | предупреждение |
| `estimatedSec` расходится с расчётным более чем вдвое | предупреждение |

Валидатор — общий модуль, он же выполняется на сервере при импорте.
Клиент не может опубликовать то, что сервер не примет.

## 9. Расширения, заложенные в формат заранее

- **Локализация.** Любое текстовое поле принимает `{ "ru": "...", "en": "..." }`
  вместо строки. Тот же приём, что в проекте «Чистый берег».
- **Озвучивание пассажира.** У узла может быть `freeform: { goal, emotion }` —
  цель и эмоция реплики пассажира для будущей генерации формулировок.
  Сам свободный ответ проводника уже работает и генерации не требует:
  реплика относится к варианту узла по `keywords` нашим распознавателем
  (`docs/INTENT.md`), офлайн и детерминированно.
- **Ротация.** `variants[]` у узла — несколько формулировок одного и того же
  выбора; движок берёт одну по сиду прохождения. Заученный путь не работает.
- **3D.** Узел `spatial` описывает цели в долях координат, что переносится
  и на схему, и на будущую VR-сцену без изменения формата.

## 9а. Линия

Сценарий ссылается на линию идентификатором, а физику — километраж, профиль
скоростей, тормозные пути, расписание — держит отдельный документ
`content/lines/*.json`. Он не версионируется вместе со сценариями: это
справочные данные инфраструктуры, а не учебный материал.

Что оттуда берётся и что из этого подтверждено открытыми источниками,
а что рассчитано нами — в [docs/LINE.md](LINE.md).

## 10. Ограничения формата (честно)

- Нет циклов с накоплением: граф направленный ациклический, кроме явных
  `retry`-рёбер. Это упрощает античит и валидацию, но не позволяет
  моделировать длинные повторяющиеся процедуры.
- Нет параллельных линий сюжета: одновременность моделируется узлом `sort`,
  а не настоящей многозадачностью.
- Состояние мира — плоский набор скаляров и флагов. Сложной симуляции
  (перемещение по составу в реальном времени, несколько NPC со своей памятью)
  формат не выдержит; для этого понадобится следующая версия схемы.

Эти границы названы намеренно: `schema` в первой строке файла существует
именно для того, чтобы вторая версия формата могла быть другой.
