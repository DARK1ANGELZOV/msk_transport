# ЭКИПАЖ 400

Тренажёр поездной бригады ВСМ. Решение для трека «Геймификация для ВСМ»
Хакатона Московского транспорта (МТТЕХ + Фонд «Транспортные инновации Москвы»).

**Проводник проходит рейс Москва — Санкт-Петербург, принимает решения под
таймером, видит последствия и получает не «очки», а измеримый профиль
компетенций.** Методист собирает сценарии сам, в браузере. Начальник резерва
видит готовность бригад к допуску.

---

## Быстрый старт

Нужен **Node 22.5 или новее**: база подключается встроенным модулем
`node:sqlite`, поэтому у сервера ноль внешних зависимостей.

```bash
npm install
npm run seed          # 12 сценариев, 12 учёток, 75 сыгранных рейсов
npm run build
npm start             # http://localhost:8787
```

Разработка с горячей перезагрузкой — `npm run dev`
(API на 8787, интерфейс на 5173, запросы проксируются).

Через Docker:

```bash
docker compose up --build
docker compose exec app node tools/seed.mjs
```

### Демонстрационные учётки

| Роль | Логин | Что видит |
|---|---|---|
| Проводник | `demo` | рейсы, разбор, профиль компетенций, рейтинг |
| Методист | `method` | редактор графа, статистика по узлам |
| Начальник резерва | `boss` | тепловая карта бригад, готовность к допуску |

Пароль общий, печатается при `npm run seed` (по умолчанию `krechet-2028`,
переопределяется `SEED_PASSWORD`). **Пароля по умолчанию в системе нет:**
без `npm run seed` не существует ни одной учётной записи. Для установки
у заказчика демо-данные не заливаются вообще.

## Что здесь работает по-настоящему

Не «прототип с заглушками». Ниже — то, что можно проверить руками за пять минут.

**Оценку считает сервер, а не клиент.** Клиент присылает *путь*: список узлов,
выборов и таймингов с точностью до десятой доли секунды. Сервер проигрывает
этот путь по своей копии опубликованной версии графа и получает результат сам.
Подделанный путь отклоняется и сохраняется как спорный — он не пропадает,
его видит методист. Проверить: `node e2e/flow.mjs`.

**Ядро одно на клиент и сервер.** Каталог `engine/` — обычный ESM без сборки,
его подключает и Node, и Vite. Игрок видит на экране те же числа, которые
сервер потом пересчитает у себя, потому что это буквально один и тот же код,
а не две реализации, которые кто-то синхронизирует.

**Своими словами, а не четырьмя кнопками.** В режиме «Живой разговор»
проводник отвечает свободной репликой, и тренажёр относит сказанное
к одному из размеченных вариантов узла. Распознаватель написан нами,
работает офлайн и детерминирован: ни языковой модели, ни ключа API.
В разборе видно каждое сработавшее слово и его вес. Сервер прогоняет ту же
реплику через тот же код и обязан получить то же ребро — иначе прохождение
отклоняется. Замер: **98,8 % попаданий на 94 контрольных репликах,
ноль подмен** (`npm run bench:intent`). Подробно —
[docs/INTENT.md](docs/INTENT.md).

**Никакого ИИ в расчётах.** Ветвление, шкалы, компетенции, время и достижения
считает арифметика из `engine/`. Распознавание речи — тоже наша арифметика,
а не чужая модель. Единственное место, где языковая модель уместна, —
черновик сценария для методиста, и он честно оставлен в дорожной карте.

**Экзамен не отдаёт ответы вместе с вопросом.** В режиме экзамена сервер
вырезает из графа подсказки, объяснения, ссылки на СОП и эталонный путь.
В тренировке всё это приходит: там объяснение и есть учебный материал.

**Основной режим — смена целиком, а не отдельное упражнение.** Четыре инцидента
подряд по километражу одной линии, между ними поезд действительно едет.
Вагон, которому нахамили на пятьдесят пятом километре, встречает вас
на сто двадцать шестом всё ещё раздражённым; усталость копится, и с каждым
инцидентом стресс уже не спадает до прежнего уровня. Это и есть перенос
методики LOFT: тренируется рейс, а не эпизод.

**Поезд едет по-настоящему.** Сценарий задаёт только километр, на котором
начинается эпизод. Скорость, время суток, расстояние и время до ближайшей
остановки, тормозной путь — считает модель линии: 679 км, профиль ограничений,
разгон и торможение с реальными замедлениями. Поэтому у каждого варианта рядом
с ценой в секундах написана цена в метрах, а окно заказа медиков закрывается
не по таймеру, а по километру. Подробности и границы модели —
[docs/LINE.md](docs/LINE.md).

**Проценты нормируются по диапазону графа.** Ноль — худший проходимый путь,
сто — лучший; обе границы считаются перебором всех путей и одинаковы для всех.
Без нижней границы даже безнадёжное прохождение давало за восемьдесят
процентов, и метрика переставала отличать сильного проводника от слабого.

## Механики

| Механика | Что делает |
|---|---|
| **Цена секунды** | У каждого действия есть цена в секундах рейса — и она же показана в метрах пути: 12 с на 360 км/ч — это 1,2 км |
| **Точка невозврата** | Окно, в которое диспетчер успевает вызвать медиков на станцию, закрывается по километру. На полосе маршрута видно, как состав в него въезжает |
| **Тормозной путь** | Экстренное торможение с 400 км/ч — 6,5 км. Поэтому перемещать пассажира на ходу нельзя, и движок это знает |
| **События мира** | Тоннель, съёмка на телефон, проход точки заказа медиков — привязаны к секундам рейса, а не к действиям игрока |
| **Обход недоступного узла** | Связь пропала — экран доклада не открывается, рейс уходит в ветку «связи нет» |
| **Стресс и туннельное зрение** | Выше 70 интерфейс сужается: часть вариантов уходит под «показать все», раскрытие стоит 3 секунды |
| **«Вдох»** | −20 стресса, +4 секунды рейса. Настоящий трейд-офф |
| **Три видимые шкалы** | Безопасность, лояльность пассажира, настроение вагона — последняя ловит классическую ошибку «успокоить одного за счёт вагона» |
| **Пять типов узлов** | Диалог, чек-лист, доклад по блокам, приоритеты, клик по схеме вагона |
| **Таймаут как ветка** | Не поражение: мир меняется, рейс продолжается |
| **Перенос состояния** | Между инцидентами смены переносятся настроение вагона, усталость и флаги вроде «вас снимают». Лояльность и безопасность — нет: пассажир другой, а регламент меряется в каждом эпизоде |
| **Неполное восстановление** | На перегоне вагон отходит асимптотически и не больше чем наполовину, а пол усталости с каждым инцидентом поднимается |

## Обучение, а не игра

- **Профиль компетенций** вместо очков: семь осей, свежие рейсы весят больше
  старых (период полураспада 45 дней).
- **Адаптивный подбор**: просроченное повторение важнее нового материала,
  среди нового первым идёт то, что закрывает слабое место.
  Интервалы Лейтнера 1 → 3 → 7 → 21 → 60 дней.
- **Разбор рейса**: карта решений, непройденные ветки, эталон по СОП,
  лента потерянного времени, «на этом узле так же поступают N % проводников»,
  комментарий наставника.
- **Достижения**: условие видно до получения, ничего «за участие».
- **Рейтинг**: командный в первую очередь, только суммирующиеся показатели,
  сезон обнуляется каждый месяц. Слабые места видит сам сотрудник
  и его наставник — больше никто.

## Структура

```
engine/          ядро: один код для клиента и сервера
  line.js        физика линии: положение, скорость, торможение, точка невозврата
  trip.js        смена: перенос состояния между инцидентами и свёртка
  grade.js       расчёт одного прохождения
  model.js       компетенции, шкалы, константы, порог допуска
  replay.js      детерминированный проигрыш пути
  scoring.js     перебор путей, потолок и пол, нормировка
  achievements.js
  recommend.js   слабое место + интервальное повторение
  validate.js    правила корректности графа
  index.d.ts     типы для клиента

server/          Node без внешних зависимостей
  index.js       маршруты
  lib/db.js      SQLite через node:sqlite
  lib/auth.js    scrypt, сессии в HttpOnly-куке
  lib/http.js    ответы, тело, ограничение частоты

src/             клиент React + TypeScript + Tailwind
  game/          прохождение: общий хук инцидента, сцена, смена, полоса маршрута
  screens/       вход, рейсы, профиль, рейтинг, разбор
  methodist/     редактор графа и статистика
  manager/       готовность бригад

content/lines/       модель линии: станции, ограничения, расписание, физика
content/trips/       смены: последовательности инцидентов по километражу
content/scenarios/   12 сценариев в открытом JSON
content/intent-bench.json  контрольные реплики для замера распознавания
docs/                концепция, формат сценария, питч
tools/               валидатор, замер распознавания, наполнение демо-данными, dev
e2e/                 сквозные тесты в браузере и снимки экранов
tests/               тесты ядра
```

## Проверки

```bash
npm run validate     # 12 сценариев против правил формата
npm test             # 51 тест ядра: физика линии, смена, оценка, античит, речь
npm run bench:intent # 94 контрольные реплики: точность распознавания речи
npm run typecheck    # строгий TypeScript
npm run test:e2e     # 25 проверок против живого сервера, включая CORS и обход каталога
npm run test:trip    # полная смена в настоящем браузере: инструктаж, перегоны, разбор
npm run test:speech  # свободная реплика в браузере: от ответа до объяснения в разборе
npm run test:shots   # снимки экранов (нужен локальный Chrome)
```

`npm run check` прогоняет первые четыре.

Тесты ядра проверяют ровно то, на чём держится доверие к продукту:
эталонный путь даёт эталонный результат, подделанный путь отклоняется,
промедление закрывает варианты, отклонённое прохождение не приносит достижений.

## API

| Метод | Назначение |
|---|---|
| `POST /api/login` · `POST /api/logout` · `GET /api/me` | сессия в HttpOnly-куке |
| `GET /api/scenarios` · `GET /api/scenarios/:id?mode=` | список и граф под режим |
| `GET /api/trips` · `GET /api/trips/:id` | смены: список и пакет с линией и инцидентами |
| `POST /api/trip-runs` | сдать смену целиком |
| `POST /api/runs` | сдать путь, получить результат и разбор |
| `GET /api/runs/:id` | разбор рейса |
| `GET /api/profile` | компетенции, ачивки, серия, что дальше |
| `GET /api/leaderboard` | бригады и личный зачёт |
| `GET /api/methodist/scenarios` · `/:id` · `POST /publish` · `/validate` | редактор |
| `GET /api/methodist/stats/:id` | статистика по узлам графа |
| `GET /api/manager/overview` | готовность бригад |

Роли проверяются на сервере: проводник получает 403 на кабинеты методиста
и руководителя, и это покрыто тестом.

## Что честно не сделано

Команда, которая сама называет границы, вызывает больше доверия, чем команда,
которая обещает всё.

- **Реплика набирается, а не произносится.** Свободный разговор работает
  с текстом; диктовка голосом (Web Speech API — в браузере, без сервера
  и без ключей) не сделана. Для распознавателя это ничего не меняет:
  он получит ту же строку.
- **Опечатки не лечатся.** «даложу» не совпадёт с «доложу»: сравнение идёт
  по основам, а не по расстоянию между словами. Заметно при наборе
  с телефона; разобрано в [docs/INTENT.md](docs/INTENT.md).
- **Черновик сценария из регламента не сделан.** Это единственное место,
  где мы считаем языковую модель уместной, и оно осталось в дорожной карте.
  Мы не показываем в интерфейсе слово «ИИ» там, где его нет.
- **Формулировки СОП — допущение команды.** Они помечены в
  `authoring.assumptions` и выводятся в интерфейсе. Перед внедрением
  заменяются на действующие документы перевозчика.
- **Дуэли есть в API и в схеме базы, но без интерфейса.**
- **Смена одна.** Контент рассчитан на один маршрут «Рейс 701»; вторая смена —
  это ещё один файл в `content/trips/`, но её никто не написал.
- **Офлайн — очередь, а не полноценный PWA.** Прохождение складывается
  в localStorage и уходит при появлении сети; service worker не написан,
  так что закешировать сценарии заранее пока нельзя.
- **Нет управления учётными записями.** Пользователи заводятся только
  скриптом `tools/seed.mjs`; экрана администратора и импорта из кадровой
  системы нет.
- **Сессии живут в памяти процесса.** Перезапуск сервера разлогинивает всех.
- **Ограничение частоты живёт в памяти процесса.** Этого хватает против
  скриптов, но не против распределённой нагрузки: настоящий рубеж —
  обратный прокси перед сервисом.
- **SQLite в одном файле.** Точка, где это перестанет работать, названа:
  десятки тысяч событий в сутки, дальше PostgreSQL. Схема переносится
  один в один.
- **xAPI / cmi5, SSO, VR** — дорожная карта, а не обещание.

## Фактура о ВСМ

Подтверждено открытыми источниками (сентябрь 2026): длина 679 км, до 400 км/ч,
время в пути около 2 ч 15 мин без остановок, состав остановок, «Белый кречет» —
8 вагонов и 454 места, запуск планируется на 2028 год, московский терминал —
Рижская, тоннелей на трассе нет (около 70 % земляное полотно, 30 % эстакады).

Рассчитано нами и подлежит замене при внедрении: километровые отметки станций,
профиль ограничений скорости, параметры разгона и торможения, сроки
согласования с диспетчером. Разделение продублировано в самом файле линии
и разобрано в [docs/LINE.md](docs/LINE.md).
